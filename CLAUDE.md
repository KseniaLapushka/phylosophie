# Контекст проекта для Claude

Личный сайт с конспектами философских курсов (школа «Архитектор смыслов»,
Андрей Баумейстер). MkDocs Material → GitHub Pages.
Репозиторий `KseniaLapushka/phylosophie`, ветка `main`, сайт собирается
GitHub Actions (`.github/workflows/deploy.yml`) при каждом пуше.
Общая справка по запуску и структуре — в `README.md`. Здесь — то, чего
в README нет: правила работы и договорённости с пользователем.
Пользователь пишет по-русски; отвечать по-русски, коротко, без воды.

## Главное правило: верность оригиналу

Конспект на сайте должен быть **максимально близок к исходному PDF**.
Разрешено исправлять только орфографию, опечатки и явные смысловые
ошибки (например, OCR: «Реформы Слона» → «Реформы Солона»). Нельзя
пересказывать, сокращать, «причёсывать». Цитаты, греческий/латинский/
немецкий оригинал, библиографические ссылки — сохраняются целиком.

- Перед тем как сказать «конспект полный» — **заново прочитать PDF** и
  сверить. По памяти не утверждать: дважды это приводило к пропущенным
  кускам (Понимание, занятие 3; Миропорядки, занятие 3), и пользователь
  это ловил.
- Слайды-картинки без текста (карты, картины, фото) в PDF не
  извлекаются. Тогда — структурный обзор по заголовкам слайдов и
  пометка в начале страницы («О формате…», `!!! note`). Ничего не
  выдумывать.
- Если в материалах не хватает занятия — прямо написать об этом в
  `index.md` курса (сейчас так у практикума «Трансформация»: нет занятия 2).

## Как добавить курс или занятие

1. Исходные PDF лежат в `_inbox/` (в `.gitignore`, в git их нет).
   Пользователь иногда кладёт новые PDF прямо в `docs/` — проверять
   `find docs -name '*.pdf'` и **переносить в `_inbox/`**: всё из `docs/`
   публикуется на сайте.
2. Извлекать текст через `pypdf` (`pip install pypdf` в `.venv`),
   постранично, во временный файл. Встроенное чтение PDF инструментом
   Read может отдать «media removed» без текста.
3. Структура: `docs/<slug>/index.md` + `zanyatie-NN-<тема>.md`
   (латиница в именах файлов). Каждый файл начинается с frontmatter
   `title:`, затем ссылка `[← Курс](index.md){: .back-link }`, затем H1.
   Заканчивается блоками `## Вопросы / что осталось непонятным`
   (`- [ ] ...`), `## Связанные конспекты` и строкой
   `--8<-- "copyright.md"` (подпись об авторстве курса — обязательна).
4. Оформление: цитаты — `>` с источником отдельной строкой;
   ключевая мысль — `==выделение==`; внешние ссылки — как в источнике.
5. Домашка — раздел `## Домашнее задание`. Вопросы с полем ответа:
   ```
   !!! example "Вопросы для самоконтроля"

       <div class="hw-item" data-key="q1">
         <p>1. Вопрос…</p>
         <textarea class="answer-box" data-key="q1" placeholder="Твой ответ..."></textarea>
         <span class="save-status"></span>
       </div>
   ```
   Задания без ответа («прочитайте…», «напишите текст…») — чек-листы `- [ ]`.
   Ответы сохраняются только в браузере (localStorage) — это известное
   ограничение, оно устраивает.
6. Проверить сборку: `.venv/bin/python -m mkdocs build --strict`.
   Баннер про MkDocs 2.0 в выводе — нормален; успех = «Documentation built».
7. Закоммитить и запушить в `main` (после добавления конспектов так
   делается по умолчанию). Затем — синхронизация с Obsidian (ниже).
8. Главную `docs/index.md` обновить списком курсов.

## Obsidian (постоянное правило)

У пользователя есть vault Obsidian. Всё, что добавляется или меняется
на сайте, нужно **в том же ходе** дублировать туда, без вопроса.
Путь к vault в репозитории не хранится — он в памяти Claude
(`obsidian-vault-sync`) или спросить у пользователя
(vault — вложенная папка, в которой лежит `.obsidian/`).

Инструмент: `tools/obsidian_export.py` (читать docstring).

- `create` — новый курс/занятие: создаёт новую заметку.
- `append` — если заметка уже есть: дописывает конспект **в конец**
  под `## Полный конспект (сайт)`.

**Vault и сайт расходятся**: в vault пользователь пишет свои заметки
(`## Мои заметки`), красит выделения, правит цитаты. Поэтому **никогда
не перезаписывать** существующие заметки — только `create` для
несуществующих и `append`. Скрипт сам откажется перезаписывать.
Каждый курс — отдельная папка верхнего уровня в vault; мини-курс —
подпапка внутри курса-родителя.

Выделения в Obsidian: поставлен сниппет `multi-highlight.css`
(классы `hl-green`, `hl-blue` и т. д. через `<mark class="...">`).

## Оформление сайта: что не ломать

Много итераций ушло на дизайн в духе «чтение»: узкая колонка, левое
оглавление с подсветкой раздела, тёплые цвета.

- Шрифт **PT Serif** (нужна кириллица; Newsreader кириллицы не имеет).
- В `mkdocs.yml` у палитры **нет** `primary`/`accent`: именованные
  палитры Material генерируют CSS, перебивающий наши переменные. Все
  кастомные переменные в `docs/stylesheets/extra.css` — с `!important`.
  Фон: светлая `#faf9f5`, тёмная `#151515`.
- Заголовок сайта в шапке — ссылка на главную, делается JS
  (`initTitleLink()` в `docs/javascripts/answers.js`), потому что
  штатная ссылка Material скрыта CSS-ом.
- Включён `navigation.instant`: JS-хуки вешать через `document$.subscribe`,
  а не `DOMContentLoaded`.
- Интерактивное поле личных заметок на `localStorage` пользователь
  **отверг** (не сохраняется в git/между устройствами) — не возвращать.
  Личные заметки на сайте — это обычный текст, который Claude добавляет
  в `.md` по просьбе.
